## Trust boundaries and flows

1. **Request path.** Internet to WAF (TLS ends here), WAF to Kong, Kong to service, service to database. Kong is not reachable from outside the app network. The two Docker networks make this literal: `app` is declared `internal: true`.
2. **Identity.** Users authenticate to Keycloak and receive a short-lived RS256 JWT (5 minutes). Each API verifies signature, issuer, audience and expiry against Keycloak's JWKS, then applies role checks. Verification happens in the services as well as (in production) at the gateway.
3. **Data.** Each service has its own PostgreSQL role with table-level grants. The appointments service cannot read the patients table.
4. **AI egress.** No application holds an LLM provider key. Applications call the guardrail proxy with an internal key. The proxy is the only workload with a route to the egress zone, and the egress firewall only allows the enterprise LLM hostname.
5. **Telemetry.** Every component emits structured logs that Wazuh ingests. Logs carry request IDs and caller pseudonyms, never prompt text or PHI.
